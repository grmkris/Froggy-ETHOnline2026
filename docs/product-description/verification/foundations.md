# Verification: foundations

How to run this file: bring up one surface and keep it for the whole cluster — the deployed app signed in with a real account, or `bun run dev` locally — then read `/health` **before the first item** and write down which integrations it reports live and which stubbed, because that reading is what decides whether the money rows can pass or must be recorded `blocked (stub)`. Confirm the build with `git rev-parse --short HEAD`; the documents describe `5caed50` and this tree moves daily. Start from a default account state: the allowance at its defaults ($2 a spend, $10 a rolling day, ask above $1, expiring in 30 days), **no ask exemption left over** from an earlier "allow for this session" (one is written silently and survives), no run in flight, no waiting approval, Telegram unpaired, and no connected agents beyond the ones the agent rows create. Open one tab at 1440px wide with the OS motion setting at its default; the rows that say otherwise name the device they need. Device values are the README's: `desktop` is 1440px or wider where the navigation is the rail, `phone` is 390px where it is the pill, `keyboard` is traversal and focus, `reduced motion` is the OS or browser setting rather than a query parameter, `offline` means pulling the network rather than toggling devtools, `second tab` is the same account in another tab of the same browser, `a connected agent` is an MCP client that actually went through the consent screen, and `live credentials` is an environment where `/health` reports the relevant integration live. Between sections, end any run you started and return the allowance to its defaults; the leash rows leave rules behind. `e2e/mandate.ts` is a reasonable way to lower the approval threshold to arrange a scene — use it to arrange and observe, never to stand in for the interaction an item is about.

- The 8 MB replay bound ([offline and reconnection](../foundations/the-request.md#interactions-with-other-systems)) — there is no hand gesture that produces 8 MB of stream in one turn on purpose, and the observable ("the reconnecting client gets the live remainder without the beginning") needs an instrumented run.
