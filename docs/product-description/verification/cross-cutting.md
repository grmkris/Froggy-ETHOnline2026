# Verification: cross-cutting

How to run this file: start from a signed-in workspace with the default allowance in force (up to $2.00 a payment, $10.00 a day, asking above $1.00, 30 days), the appearance preference at **Passbook**, the daily digest **off**, Telegram **unpaired**, and no open approvals. Read `/health` before the first item and write down which integrations it reports live — that reading decides which rows can pass and which are `blocked (stub)`. Almost every item here is a _consistency_ check: do the thing on one surface, then read the same fact on a second, and the row passes only when the two agree. Clear between sections by reloading the tab (which drops the tab's own markers, notices and drafts) rather than by signing out, unless the row says otherwise.

Device column values: **desktop** (1440 px or wider, navigation is the rail); **phone** (390 px, navigation is the pill); **keyboard** (traversal, focus, Enter/Escape, no pointer); **screen reader** (VoiceOver, NVDA or Orca actually running, not an accessibility inspector); **reduced motion** (the OS or browser setting, not a query parameter); **offline** (the network pulled, not a devtools toggle); **second tab** (the same account in a second tab of the same browser); **second device** (genuinely a second device); **a paired phone** (Telegram paired to this account through `/start CODE`); **a connected agent** (an MCP client that went through the consent screen, not a token pasted into a script); **two agents** (two separately consented connections); **stubbed build** (a keyless local build on loopback, where `/health` reports stubs); **live credentials** (an environment where `/health` reports the relevant integration live). A row marked `live credentials` needs real money, a real Hedera transaction or a live Graph key: on a stubbed run record `blocked (stub)`, never `pass`.

- Whether every record's revision prevents two writers clobbering one another: needs two concurrent writers arranged deliberately, which the interface does not offer.
