# Verification: workspace

How to run this file: bring up the surface as [the protocol](README.md#how-to-run-a-pass) says, read `/health` first and write down which integrations are live, and sign in as one person with one Telegram account, one connected agent and one browser profile — several rows below need a second tab of that same browser and a few need a genuinely second device. Start each document from a fresh page load at the default preferences: Passbook appearance, reduced motion off, no `?theme=` in the URL, the Services tab on Explore, and the four Activity filters at "All". Between sections, clear what the previous one left behind: cancel any schedule you created, answer or let expire any approval still open, close the Add funds dialog, and press **Stop** on anything still running. Device column values are the ones [the protocol](README.md#devices-and-conditions) defines — `desktop` (1440px, the rail), `phone` (390px, the pill), `keyboard`, `reduced motion`, `offline`, `second tab`, `second device`, `live credentials`, `a connected agent`. **A row marked `live credentials` cannot pass on a stubbed build**: run it anyway, watch what happens, and record `blocked (stub)` rather than `pass`, because a stubbed run never verifies a claim about money, provenance or a live service. Rows marked "(suspected bug)" expect nothing in particular — write down what the product did, and file it in [bug-triage.md](../bug-triage.md) against the entry named in the Claim.
