# IDEAS v2 "No Flake": everyone stakes $10 to a plan; the agent polls, finds a slot and BOOKS in the shared browser; show up and get it back, flake and the group splits your stake

**Money model:** Hackathon version has no revenue and moves no real value. Per plan: each member stakes $10 test-USDC (Base Sepolia) into PlanEscrow; attendees get exactly their stake back plus an equal share of every no-show's stake, computed by the contract; if nobody checks in, or any member disputes inside the window, refundAll() returns everything (forgiving default, per IDEAS_KIMI's own 'opt-in, forgiving defaults' note). The agent's tool spend is separate: a per-plan HBAR budget (default about 0.5 HBAR testnet) from the host-held pocket pays the x402 venue-finder per result; the organizer sees and can lower it. No rake, no fee, no fiat, no on-ramp (mocked/faucet, which the Privy track allows: 'Features requiring commercial or guided onboarding may be mocked'). Post-hackathon model (INFERRED, not built): never a rake on forfeits (that is the line IDEAS_KIMI's legal scan drew and the Bafin/MiCA 'professional basis' trigger in dim-safety); revenue if any comes from venue-side referral or a premium organizer tier. State plainly in README: 'we hold no funds; a contract holds stakes; our referee key can only call settle or refund'.

**Custody / who authorizes money movement:** Four money movements, each with one named authorizer. (1) Stake in: the MEMBER, in their own browser, after Privy Telegram login; the user-owned embedded wallet signs eth_sendTransaction USDC.approve + PlanEscrow.stake(planId, 10e6). The agent has no signer on member wallets. Optional Privy policy on member wallets: value lte 10 USDC and to in {escrow} so a spoofed link cannot stake more (stretch, not required). Gas: team prefunds each new wallet with Base Sepolia ETH + 30 test-USDC at /start (Circle faucet: 20 USDC per address per 2h, reCAPTCHA-gated, human-only; team drips from a treasury wallet). (2) Agent tool spend (x402 on Hedera): the ORGANIZER authorizes the per-plan budget when creating the plan (Telegram inline button with server nonce and callback_query.from.id check); each payment is then signed automatically by the host-held agent ECDSA account (hedera:testnet, HBAR) under a host ledger that is serialized per plan and checked before signing; kill switch = delete the key; idempotency via payment_identifier map (RESEARCH 4.2). Privy has NO policy coverage here (raw signing is outside the policy enum) and the README must say so; on testnet nothing funds this pocket except the Hedera faucet, so the 'only Privy-policied value enters the pocket' story from BRIEF does not apply and should not be claimed. (3) Settlement: the CONTRACT computes payouts; the REFEREE (a Privy server wallet, owner = team's P-256 authorization key, agent = additional signer) may only call settle(planId, bitmap) or refundAll(planId) on 0xPlanEscrow, enforced by a Privy policy with ethereum_transaction.to in_condition_set and ethereum_calldata function_name conditions with the escrow ABI (VERIFIED field sources in Privy policy overview, fetched tonight). The trigger is the agent's verdict after a dispute window; a server-side 'frozen' flag is checked before every sign because access tokens live up to 15 min. The referee cannot transfer USDC, cannot call any other contract, cannot change the split: the contract sends only to stakers. (4) Refund on dispute/void: any MEMBER taps 'Dispute' in the window -> server calls refundAll through the same policied wallet; no agent judgment involved. What the agent can never do: raise its budget, unfreeze, add a recipient, or export a key (never exposed as tools, dim-safety).
