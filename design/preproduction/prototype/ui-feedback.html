UI feedback

The four moments the interface has to get right, live and replayable. Every one is visible at rest: the motion starts from the finished state, so nothing here is parked at zero opacity waiting for a trigger.

1 · Button, pending and confirmed

Pending is a real state, not a spinner laid over something already committed, and the amount stays in the label so nobody approves an unnamed number. Success only arrives when the confirmed event does — that is the second button, standing in for the domain event. Nothing here is on a timer, because a celebration on a timer is a lie about a payment.

4 · Browser handoff
