# Design: PRIZE-FIRST. Every design choice below is picked to maximize expected partner-pr

**Angle:** PRIZE-FIRST. Every design choice below is picked to maximize expected partner-prize dollars under the verified ETHOnline 2026 rules and the empirical anatomy of winners (video shows the running product in the first 30s and a real explorer page in the back half; "How it's made" names facilitator/network/price and admits the hack; per-sponsor evidence files; live URL alive). The product is ONE job (find the cheapest USDC borrow across standardized lending subgraphs, then buy a 24h rate watch from an x402 service on Hedera) executed by an agent in a Chrome you can watch, grab and freeze, spending under a Privy policy on the EVM leg and a host-capped HBAR pocket on the Hedera leg. Testers are built and counted only as the Hedera rubric's Validation item (15/100 if the hedera-skills rubric is used) and as WOW evidence; nothing is built for testers that a judge will not see. Sponsors stay Privy + The Graph + Hedera (five tracks, three slots). Nothing else on the prize board is touched.

**Names:** Reins (hold the reins on the agent's browser and wallet; reins.sh / reins.wtf); Dual Control (driving-school cars have a second brake; the human has one here); Chaperone (an agent with a chaperone, not a key); Handbrake (the kill switch is the product); Backseat (you ride along and can grab the wheel)

**One sentence:** Reins is an open-source agent wallet where the AI drives a real Chrome you can watch, grab and freeze, and can only spend inside a Privy policy: it pays The Graph $0.01 per standardized-subgraph query from the user's Privy wallet and pays an x402 rate-watch service on Hedera (Blocky402) from a host-capped HBAR pocket, with every spend receipted (deployment ids, tx ids, policy id, HCS message).

**Tagline:** An agent browser you can grab, a Privy leash it can't slip, x402 paid on The Graph and Hedera.

**20s pitch:** Every agent wallet shipped this year hands a model a key and a cap; you never see what it does with the key. Reins gives the agent a Chrome you can watch and grab, and a wallet whose rules live outside the model: a Privy policy caps every EVM signature, a host ledger caps the Hedera pocket, and one Telegram tap freezes both. In the demo it finds the cheapest USDC borrow across Aave, Compound and Spark, paying The Graph per query, then buys a 24-hour rate watch on Hedera through Blocky402, gets an HCS receipt, and refuses to send anything to 0xevil, because Privy says no, not the prompt.

**Custody and policy:** Two pockets, stated honestly. (1) USER WALLET: a Privy embedded wallet created server-side at first web login (privy.wallets().create with owner = user, agent = additional_signer with override_policy_ids [pol_agent]); user logs in with email OTP or Telegram OAuth in their own browser (never inside the agent Chrome). Dashboard: auto-create-embedded-wallet OFF. The agent signer's policy pol_agent (default DENY) has exactly three ALLOW rules: (a) eth_signTypedData_v4 with ethereum_typed_data_domain.chainId = 8453 AND verifyingContract = 0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913 AND TransferWithAuthorization.value <= 20000 AND .to in {0x79DC34E41B2b591078d3dE222C43EcaaBD52FcCB} (Graph x402, $0.02 per payment cap, payTo allowlist; the types map copied byte-for-byte from the first real signing request); (b) eth_signTransaction (host broadcasts, NOT eth_sendTransaction, because only eth_signTransaction carries stateful aggregations) with to = the agent pocket's address, value <= per-tx cap, and a rolling 86400s sum <= daily cap; (c) nothing else, so 'send to 0xevil' is denied by Privy itself. Daily cap on x402 typed data is NOT enforceable in Privy today (aggregations cover eth_signTransaction/eth_signUserOperation only); the host keeps a serialized per-session USDC ledger checked BEFORE requesting a signature and says so in README. Wording everywhere: 'enforced server-side under policy', never 'in the enclave'. (2) AGENT POCKET on Hedera testnet: an ECDSA account whose key lives only on the host (createClientHederaSigner from @x402/hedera 2.25.0), HBAR asset 0.0.0, host-enforced per-tx and daily caps, x402 idempotency map keyed on (resource URL, 402 nonce) so a retried fetch never re-signs. Privy CANNOT policy-gate this leg (secp256k1_sign/raw_sign are not in the policy method enum; Hedera is Tier 1); we do not build the raw-sign wrapper. The only way value enters the pocket is the Privy-policied transfer in rule (b): D1 spike tries Privy eth_signTransaction on eip155:296 via Hashio (HBAR from the user's own Hedera EVM alias to the pocket, HashScan-visible); if that fails within 30 min the fallback is a policied USDC transfer on Base to the host treasury that credits testnet HBAR at a fixed documented rate ('the bridge is us', disclosed). KILL SWITCH: Telegram inline button (server nonce + callback_query.from.id check) or wallet-pane Freeze -> remove the agent signer from the wallet (immediate), set a server 'frozen' flag checked before every sign (agent access tokens live up to 15 min), delete the pocket key, abort the run. Never exposed as an agent tool: freeze, raise_limit, resolvePermission, policy edits. README sentence, verbatim: 'Privy's policy engine gates every EVM signature the agent produces (x402 EIP-3009 payments to The Graph and pocket top-ups) with a per-payment cap, a rolling daily cap on top-ups, a recipient allowlist and a kill switch. Hedera transactions are raw-signed and Privy only evaluates policies on transactions it can decode, so the Hedera x402 leg is paid from a separate host-held pocket with host-enforced caps; the only way funds enter that pocket is a Privy-policied transfer, and the kill switch deletes the pocket key.'
